# The AI-taught parser

LogLens recognizes common log formats on its own. For everything else it has a generic parser, which finds timestamps, levels and components by looking for familiar shapes. Some logs have none of those shapes: in-house formats, industrial equipment, game servers. For these, LogLens can ask a language model to **write a parser**. The parser is a small YAML plugin that LogLens validates on the file itself before using it. After that, the model is no longer needed: the plugin runs locally, at full speed, on any number of files.

```bash
loglens learn my.log                 # learn one file
loglens parse logs/ -o out --learn   # learn every file parsed with low confidence, then parse again
```

## How it works

1. **Sampling.** LogLens reads up to 10,000 records of the file and groups them by *line shape*: digits become `9`, letter runs `a`, punctuation stays. It then takes about 50 samples round-robin across the shapes, so rare record types (a fault, a stack trace) are included, not just the most frequent line repeated 50 times.
2. **One call.** The samples go to Gemini in a single structured-output request. The JSON schema covers the regex with named groups, the timestamp formats, the level mapping, and an optional record-start rule for multi-line records.
3. **Validation.** The answer becomes a format definition, and LogLens checks it on up to 10,000 records:
   - the definition loads: the regex compiles, has named groups, and matches its own sample lines;
   - what share of records it matches;
   - what share of timestamps parse;
   - what share of levels map to the normalized scale.
4. **Retries.** Below a 95% match rate, LogLens asks again, at most 3 times. Each retry shows the model its previous definition and the records it missed, even when that definition could not be loaded at all.
5. **Saving.** The best definition is saved in `~/.loglens/formats/` with its provenance (`generated_by: ai`, model, date, measured match rate). From then on it is a format like any other: `detect` and `parse` use it, `formats list` shows it, `formats test` re-measures it, and you can edit it by hand.

In interactive mode, nothing is sent until you have seen the exact sample lines and agreed. `--yes` skips the question. Responses are cached on disk, keyed by a hash of the request, so running the same command again costs nothing.

## Before and after: three formats LogLens had never seen

Three synthetic logs, invented for this test and generated by [`tests/fixtures/make_exotic_fixtures.py`](../tests/fixtures/make_exotic_fixtures.py). No real data was used. No built-in parser recognizes any of them.

**Industrial PLC alarm journal.** Day-first dates with two-digit years and a decimal comma, a CPU path, three-letter states, alarm numbers, and indented detail lines under faults:

```text
14.03.26 06:00:08,063  ET200SP/IM155  FLT 0903  Safety relay K6 tripped, line 6 stopped
    > input I4.0 = FALSE
    > last OK cycle: 105 ms ago
14.03.26 06:00:15,758  ET200SP/IM155  ACK 0099  Alarm 977 acknowledged by operator 7
```

**Game server.** Year/day-of-year dates, one-letter severities, match or subsystem context:

```text
[2026/073-06:00:02.130][I][match#8812] KILL Mira -> noob_7 (deagle, headshot, noscope)
[2026/073-06:00:03.732][E][anticheat] Sn1per_42 flagged: aim snap 731 deg/s
```

**Pipe-delimited service log.** Basic-ISO timestamps, host, service, one-letter level, an order ID or `-`, the message, then zero to three `key=value` fields. The column count varies, so it is not CSV:

```text
20260314T060001.244Z|web-04|search|E|-|payment declined: card expired|shard=5|retry=1
20260314T060002.085Z|web-06|checkout|W|-|slow query took 3469 ms|attempt=2
```

Measured with [`benchmarks/exotic_bench.py`](../benchmarks/exotic_bench.py), which runs the full pipeline (2,000 lines per file):

**Before** (built-in formats and the generic parser):

| File | Format | Events | Confidence | Timestamps | Levels | Components | Templates |
|---|---|--:|--:|--:|--:|--:|--:|
| game_server.log | `free_text` | 2,000 | 0.22 | 0% | 0% | 0% | 10 |
| pipe_service.log | `free_text` | 2,000 | 0.23 | 0% | 0% | 0% | 85 |
| plc_alarm.log | `free_text` | 1,796 | 0.54 | 0% | 0% | 0% | 10 |

**After** `loglens learn` (one call per file):

| File | Format | Events | Confidence | Timestamps | Levels | Components | Templates |
|---|---|--:|--:|--:|--:|--:|--:|
| game_server.log | `game_server_log` | 2,000 | 1.00 | 100% | 100% | 100% | 14 |
| pipe_service.log | `pipe_delimited_service` | 2,000 | 1.00 | 100% | 100% | 100% | 7 |
| plc_alarm.log | `plc_system_log` | 1,796 | 1.00 | 100% | 100% | 100% | 10 |

All three definitions reached a 100% match rate on the first attempt; no retry was needed. They are kept unedited in [`examples/formats/`](../examples/formats/), and a test checks they still parse their logs fully. Some details worth noting:

- **PLC:** the model also produced a `record_start` rule, so the indented detail lines stay attached to their fault. It extracted the alarm number into its own field (`code_id`) and mapped `ACK` (acknowledged) to `INFO`, a sensible call no generic rule would make.
- **Game server:** the `strptime` pattern `%Y/%j-%H:%M:%S.%f` reads the day-of-year date correctly. The match or subsystem (`match#8812`, `anticheat`, `net`) becomes the component.
- **Pipe-delimited:** host and order ID become fields. The before run had 85 templates, because the generic parser saw the whole line as message text. After, only the real messages are mined, giving 7 templates for 7 kinds of events.

## Limits

- **Variable tails stay in the message.** In the pipe log, the optional `|retry=1|shard=5` fields stay at the end of the message instead of becoming fields: one regex cannot name a variable set of keys. Template mining still masks their values, so grouping is unaffected.
- **Closed lists in learned regexes are brittle.** The PLC regex lists the five states it saw (`ALM|FLT|WRN|INF|ACK`). A sixth state would not match, and that record would get low confidence instead of crashing; `formats test` shows such misses. Because definitions are plain YAML, the fix is a one-line edit.
- **The sample decides what the model sees.** Sampling by line shape covers rare record types, but a type that never appears in the first 10,000 records is never shown to the model or validated.

## Cost and the free tier

Run on 2026-10-07 with the Gemini free tier:

| Step | Model | Calls | Input tokens | Output tokens |
|---|---|--:|--:|--:|
| `loglens doctor` test call | gemini-3.8-flash | 1 | 8 | 81 |
| pipe_service.log | gemini-3.8-flash | 1 | 2,919 | 2,026 |
| plc_alarm.log | gemini-3.5-flash-lite (fallback) | 1 | 3,286 | 349 |
| game_server.log | gemini-3.5-flash-lite (fallback) | 1 | 2,852 | 253 |
| `parse --learn` end-to-end check | gemini-3.5-flash-lite | 1 (+2 cached) | 2,919 | 285 |
| **Total** | | **5** | **11,984** | **2,994** |

The output tokens of `gemini-3.8-flash` include its thinking tokens, which explains the 2,026.

What happened along the way, and what it changed in LogLens:

- The first two learning runs hit **503 "model overloaded"** errors. LogLens retried 5 times with exponential backoff and then stopped with a clear error, as designed. But each of those attempts counted against the daily quota.
- The free tier allowed only **20 requests per day for `gemini-3.8-flash`**, so the failed retries used up the quota. LogLens recognized the per-day quota error and said so, rather than retrying.
- Two changes followed (docs/decisions.md D20):
  - Retries are fewer and slower: 3 by default, at least 10 s apart after a 5xx error.
  - Free-tier quotas are counted per model, so LogLens now falls back to another model when the main one is exhausted or still unavailable after its retries (default `gemini-3.5-flash-lite`; `LOGLENS_LLM_FALLBACK_MODELS` or `fallback_models` in `config.yaml`). The switch is printed under the token summary. The remaining two files were learned this way.
- The end-to-end `parse --learn` check reused two cached answers. The third answer had been cached under the main model's name; since that model was out of quota, the fallback answered it with one new call. The cache is per model on purpose: answers from different models are not interchangeable.

## Privacy

Learning sends about 50 lines of your log to Google. On the free tier, Google may use prompts and responses to improve its products. Only send logs you are allowed to share. Without `--yes`, LogLens shows the exact lines first and asks. `--no-ai`, `LOGLENS_AI=0`, or `ai: false` in `~/.loglens/config.yaml` turns every AI feature off. You can also write the plugin yourself with `loglens formats new`, which needs no AI at all.
