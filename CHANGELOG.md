- Step 2: ingestion layer (`loglens.ingest`).
  - `iter_lines(inputs, options=, report=)` lazily yields `Line(source_file, line_number, text)` from files, recursive folders, and stdin (`-`).
  - Transparent `.gz`, `.bz2`, `.zip`, `.tar` (and `.tar.gz`/`.tar.bz2`) at any nesting depth, detected by magic bytes rather than extension. Members are named `archive.zip!/inner/file.log`. Zips from non-seekable streams are spooled to a temp file (disk, not RAM); tars are streamed.
  - Binary files skipped (NUL byte or >30% control characters in the first 8 KB).
  - Encoding per file: BOM (UTF-8/16/32), BOM-less UTF-16 heuristic, strict UTF-8, then charset-normalizer, with exact ties broken toward cp1252; fallback UTF-8 with `errors="replace"` plus a warning.
  - `\n`, `\r\n`, `\r` normalized, including across read boundaries. Only those three split lines (not U+2028, `\x0b`, etc.).
  - Constant memory: streaming decode; lines longer than `max_line_chars` (default 1,000,000) are yielded in pieces with the same line number, with a warning.
  - `IngestOptions`: include/exclude globs (matched on full path and basename; filter discovered files, not explicit ones; exclude prunes directories), `max_line_chars`, `max_archive_depth`.
  - `IngestReport`: files read, files skipped with reason, warnings, bytes read, encoding per file.
  - Never raises on bad input: missing, unopenable, corrupt or truncated files and archives, encrypted zip members are all reported.
  - Fixtures in `tests/fixtures/ingest/` (UTF-8, Latin-1, UTF-16 BOM, CRLF, nested zip, gz, binary, empty), generated deterministically by `tests/fixtures/make_ingest_fixtures.py`; `.gitattributes` keeps them byte-exact.
  - New dependency: `charset-normalizer`.
  - 89 new tests, including Hypothesis round-trip properties and tracemalloc memory tests (40 MB file, 24 MB gzip, 24 MB single line: peak < 4 MiB).
- Step 3: record splitting (`loglens.split`).
  - `iter_records(lines, options=, report=)` lazily groups ingested lines into `Record(source_file, line_start, line_end, text)`; records never span files.
  - Per-file record-start signature learned from the first `sample_lines` (default 1000) lines. Candidates, most specific first: `timestamp` (ISO, day/month-first, syslog, Apache, RFC 2822, time-only, glog, epoch; optional leading bracket), `level`, `json` (`{` at column 0), `bracket` (`[...]`, `<PRI>`).
  - Scoring: a candidate must match at least one line and either explain ≥ 80% of the sample (starts plus continuation-looking lines: indented, `at `, `Caused by:`, `... N more`, `Traceback`, exception names, closing braces) or cover ≥ 30% of it (admits unindented multi-line SQL). Best (explained, coverage) wins; ties go to the more specific signature.
  - Fallback without a signature: `unindented` (only unmistakable continuations attach, so uniform files give one record per line), or `every-line` when most of the sample is indented.
  - Records are capped at `max_record_lines` (default 500): overflow starts a new record, counted per file in `SplitReport.warnings` and logged via `logging`.
  - Pieces of over-long lines (same line number from ingestion) are rejoined into one line.
  - `SplitReport`: chosen signature per file, warnings.
  - 85 new tests: Java and Python (chained) tracebacks, every-line logs, no-timestamp files, pretty-printed JSON and JSON lines, multi-line SQL, orphan continuation lines, the giant-record cap, laziness on an endless input, ingest integration, and a Hypothesis property (records partition the input exactly, never exceed the cap). About 1.4 M lines/s.
- Step 4: format detection (`loglens.detect`).
  - `iter_detected(records, options=, report=)` lazily yields `DetectedRecord(record, format_name, confidence)`: consecutive records of one file are grouped, the first `sample_records` (default 500) are buffered and scored, then replayed (released as they go) followed by the rest of the file. Records pass through unchanged and in order; memory is bounded by the sample.
  - `detect_format(sample)` returns `DetectionResult(format_name, confidence, scores_by_format, details)`, with the score of every candidate, the winner's `details`, and a `runner_up` property. The best score wins if it reaches `min_confidence` (default 0.6); exact ties go to the candidate listed first; otherwise the file is `free_text`.
  - Detectors (`Detector(name, score)`, score = share of non-blank sample records the format can structurally parse), in priority order, most specific first:
    - `json`: the record is exactly one JSON object (arrays, scalars, trailing text rejected); pretty-printed multi-line objects count.
    - `xml`: one complete well-formed element; multi-line records may also be a well-formed prefix (wrapper such as `<Events>`, or an element cut by the record cap); closing-tag-only and `<?xml ?>` records count. Uses `xml.parsers.expat` with reparse deferral off; any DOCTYPE/ENTITY is rejected before parsing, so no entity is expanded and nothing is fetched.
    - `syslog_rfc5424`, `syslog_rfc3164` (optional `<PRI>`), `apache_combined` (also nginx's default access format), `apache_common`, `nginx_error`, `log4j` (level/thread in either order, logback time-only), `python_logging` (`asctime - name - LEVEL - msg` and `LEVEL:name:msg`): anchored regexes matched on the record's first line, so stack traces don't hurt.
    - `prefix_json`: a non-empty text prefix followed by a JSON object that runs to the end of the record (possibly multi-line), e.g. `2026-01-01T10:00:00Z INFO payments {"order": 1}`. Up to 5 `{` positions are tried, so braces in the prefix are fine. `split_prefix_json()` is public for the parsers. Placed after the known text formats: a log4j line whose message is JSON stays `log4j`.
    - `logfmt`: single-line records with at least 2 `key=value` pairs (quoted values allowed) making up at least 75% of the tokens, so one `a=b` in a sentence is not enough.
    - `csv`: `sniff_csv()` tries `,` `\t` `;` `|`; the most common field count must be at least 3 (two delimiters) over at least 2 records; score = share of records with that count; header row detected (unique identifier-like names over a column whose data has digits). TSV/semicolon/pipe are all reported as `csv`; the dialect is in the result's `details` (`delimiter=tab, columns=4, header=no`).
    - `free_text`: always applies with a fixed score of 0.1.
  - Registry: `DEFAULT_DETECTORS` is a tuple; `DetectOptions(detectors=...)` accepts extra detectors (step 5 YAML plugins), with `regex_detector` / `share_detector` helpers. A detector that raises or returns a non-number scores 0 and is reported; scores are clamped to [0, 1].
  - `DetectReport`: detection per file, `format_counts`, warnings (detector failures; structured format chosen while some sample records don't match it). Warnings are also logged.
  - Split change (step 3): new `xml` start signature (`<tag` or `<?` at column 0) and `</...>` lines count as strong continuations. Without it, pretty-printed XML events were split one line per record (most lines indented triggered the `every-line` fallback), so no record was a whole element.
  - Design notes: detectors return a plain float; a detector may also provide an optional `describe(sample) -> dict[str, str]`, called only when it wins, so format-specific details reach later stages without format-specific fields on `DetectionResult`. A failing `describe` keeps the detection and is reported. Added `nginx_error` and `apache_common` alongside the briefed formats. No new dependency (stdlib `json`, `csv`, `xml.parsers.expat`, `re`).
  - CLI: `loglens detect <paths...> [--sample N]` prints a Rich table (file, format, confidence, details, runner-up), then skipped files and detection warnings; files read but empty show as `empty`; exits 1 if nothing was readable. Reads at most `N × 50` lines per file.
  - Ingest: new `IngestOptions.max_lines_per_file` stops reading each file after that many lines (used by `detect`, which only needs a sample).
  - Fixtures in `tests/fixtures/detect/` (JSON lines, pretty JSON, CSV with header, TSV, logfmt, Windows-style XML events, syslog 3164/5424, Apache combined/common, nginx access/error, Python logging and log4j with tracebacks, free text), generated by `tests/fixtures/make_detect_fixtures.py`; marked binary in `.gitattributes`.
  - 161 new tests (157 detection, 4 split): positives and tricky negatives per detector (prose with commas, a lone `a=b`, `<` lines that are not XML, syslog `<PRI>`, JSON arrays/scalars, entity bombs), tie-breaks, mixed files, malformed records in a JSON file, ingest -> split -> detect on every fixture and on the whole folder, laziness on an endless input, and Hypothesis properties (scores in [0, 1], deterministic, records preserved in order with one detection per file).
  - Follow-up: 36 more tests (378 total, 99% coverage): `prefix_json` positives and negatives, priority against log4j and plain JSON, `details`/`describe`/`runner_up`, fixtures `prefix_json.log`, `noheader.csv` and `ambiguous.log` (logfmt and csv both score 1.0; logfmt wins on priority), the `detect` CLI, and `max_lines_per_file`.
  - README: status table and a `loglens detect` example.
- Step 5a: parsers for structured formats (`loglens.parsers`).
  - `Parser` protocol: `format_name` and `parse(record) -> ParsedEvent`. `ParsedEvent(message, timestamp_raw, level_raw, component, extra, confidence, is_event, error)` is a partial unified event: raw timestamp and level (normalization comes later), unmapped fields in `extra` as strings (non-strings rendered as JSON), `is_event=False` for records holding no event (CSV header, XML declaration or wrapper tags), and `error` explaining a (partly) malformed record.
  - `create_parser(format_name, details)` returns a fresh parser for `json`, `prefix_json`, `csv`, `logfmt`, `xml` (the names used by detection), or None. One parser per file: the CSV parser learns its header.
  - Automatic field mapping (`fields.py`): nested keys flattened with dots; each role (timestamp, level, message, component) has candidate names in priority order, compared after normalization (lowercase, `@` `_` `-` dropped), e.g. `@timestamp`/`timestamp`/`time`/`ts`/`eventTime`, `level`/`log.level`/`severity`/`levelname`/`at`, `message`/`msg`/`log`/`body`/`short_message`, `logger`/`component`/`service.name`/`kubernetes.container_name`/`name`. A few unambiguous names also match the end of nested keys (`RenderingInfo.Message`, `System.TimeCreated.SystemTime`), shallowest first. Values are checked too: timestamps need a digit, levels must be a level word or a small number, components must not start with a digit (so `service=13ms` is not a service).
  - No message field: one is built from the unmapped fields as `key=value` pairs.
  - JSON: trailing text after the object (a stray line the splitter attached) is kept in `extra["trailing_text"]` at confidence 0.5 instead of losing the event.
  - Prefix + JSON: payload fields win; the prefix fills gaps (leading timestamp, level token, single-word component); losing prefix values go to `extra` (`prefix.timestamp`, `prefix.level`, `prefix`).
  - CSV/TSV: by column name with a header; without one, roles guessed from values (timestamp-looking, level word, multi-word message) at confidence 0.8; rows of the wrong width at 0.5; strict quoting, so an unterminated quote is malformed.
  - logfmt: quoted values with JSON-style escapes, loose words become the message or `extra["text"]`, repeated keys kept as `key[2]`; confidence = share of tokens that are pairs.
  - XML: attributes and children flattened (`System.EventID`), namespaces dropped, `<Data Name="User">bob</Data>` becomes `EventData.User`, root text is `text`; wrapper closing tags attached by the splitter are ignored; DOCTYPE/ENTITY never parsed.
  - Never raises: malformed records become events with confidence 0.1, the raw text as message, and an `error`; `safe_parse()` also guards plugin parsers.
  - Realistic fixtures in `tests/fixtures/parsers/` with malformed lines mixed in: structured app logs (ECS, pino, structlog-style JSON), Kubernetes JSON (fluentd container logs, klog, controller-runtime), web-server logfmt (logrus, Heroku router), a CSV export, Windows Security events in XML.
  - 125 new tests (503 total, 99% coverage), including the full ingest -> split -> detect -> parse pipeline on each fixture, a check that every line is accounted for, and Hypothesis properties that no parser raises on arbitrary or structured-looking input.
- Step 5b: well-known text formats, declared in YAML (`src/loglens/parsers/patterns/`, one file per format; adding a format needs no Python).
  - 11 formats: `syslog_rfc5424`, `syslog_rfc3164` (also rsyslog RFC 3339 timestamps and journalctl short/short-precise/short-iso/short-unix), `apache_combined` (Nginx's default access log), `apache_common`, `nginx_error`, `log4j` (log4j, logback default, Spring Boot), `python_logging`, `go_log`, `journal_export` (`journalctl -o export`), `windows_event_csv` (Event Viewer CSV / tab-delimited export), `windows_event_text` (`wevtutil /f:text`).
  - Schema (`textformats.py` docstring): `name`, `description`, `regex` (one or a list of alternatives; named groups `timestamp`/`level`/`component`/`message`, any other group goes to `extra`), `flags`, `priority`, `timestamp_format` hints (`strptime` or `iso8601`/`epoch`/`epoch_ms`/`epoch_us`), `level` (`group`, `transform`: `syslog_priority`/`http_status`, `map` to normalized levels, `default`), `null_values`, `unquote`, `ignore` (records holding no event, e.g. a CSV header), `record_start` (multi-line records), `extra_fields` (key/value regex applied repeatedly, for fields in any order), `sample_lines` (strings or `{line, expect}`). Definitions are strictly validated with errors naming the file; samples must match at load time.
  - Every sample line is a test (`tests/test_textformats_samples.py`): expected fields, timestamps parse with the declared hints, levels normalize, the line alone is detected as its format, and the samples written to a file go through ingest -> split -> detect -> parse cleanly.
  - `TextFormatParser`: regex match, groups mapped to the schema, text after the match (stack traces, panics) appended to the message, BOM stripped, `extra_fields` collected. `ParsedEvent` gains `level`, the normalized level when the format declares a mapping.
  - Detection: the hand-written text regexes of step 4 are replaced by one detector per YAML format (score = share of matching records, ignored records excluded), placed between `xml` and `prefix_json` in priority order. The step-4 detector tests pass unchanged (the old constant names now point to the YAML formats).
  - Split: formats may declare `record_start`; `learn_signature` trusts a declared start that matches one of the first two non-blank lines, so journal export entries, wevtutil events and Event Viewer CSV rows with multi-line quoted messages are whole records. `SplitOptions(declared_starts=())` disables it.
  - `parse_timestamp(raw, hints)` (`timestamps.py`); year-less patterns (syslog) use a placeholder leap year to avoid Python 3.13's deprecation and Feb 29 failures.
  - `loglens.schema.LEVELS`: the normalized level vocabulary.
  - `parsers/patterns.py` renamed `parsers/values.py` (the name is now the YAML directory). New dependency: PyYAML (+ `types-PyYAML` for mypy). YAML files ship in the wheel (checked).
  - Benchmark `benchmarks/bench_text_formats.py`: every single-line format parses 145k-341k records/s (regex match alone 285k-2.7M/s); multi-line entries (journal, wevtutil) 61k-90k entries/s, i.e. over 1M lines/s.
  - Test change: `test_create_parser_unknown_format` asserted that `log4j` had no parser, true in 5a and deliberately false now; it now uses an unknown name, and a new test asserts `log4j` gets a `TextFormatParser`.
  - 314 new tests (817 total, 99% coverage): 222 generated from YAML samples, tricky real-world lines per format (escaped quotes, TLS probes, SD-PARAM escapes, BOM, `$` in loggers, lowercase non-levels), non-matching lines, multi-line exports through the pipeline, loader validation errors, a YAML-only new format, priorities, import order, and the benchmark script.
